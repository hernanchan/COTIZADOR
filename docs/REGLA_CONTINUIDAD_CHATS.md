# Regla de continuidad de chats — Proyecto Integral Nueva Web

Fecha de registro: 2026-10-27.

## Petición prioritaria del responsable del proyecto

**No esperar a que se agote el espacio del chat.** Avisar proactivamente al usuario con suficiente anticipación cuando la conversación ya sea larga y convenga migrar a una nueva, para preparar sin apuros un prompt completo de continuidad. El usuario perdió el contexto del chat anterior porque se alcanzó el límite y el prompt quedó truncado.

## Procedimiento de traspaso

1. Avisar antes de llegar al límite, en cuanto se detecte una conversación extensa. No afirmar conocer un porcentaje exacto de capacidad restante, porque ese contador puede no estar disponible.
2. Preparar en ese momento un prompt de continuidad **completo**, en un solo bloque copiable, incluyendo nombre de proyecto, repositorio, rama/commit vigente verificados, entorno privado, estado implementado, pendientes, fallas detectadas, próxima acción concreta, restricciones y decisiones tomadas.
3. Mantener un registro duradero en GitHub y actualizarlo antes del cambio de conversación. Si no se puede actualizar, decirlo explícitamente.
4. Indicar qué archivo y rama consultar al abrir el chat siguiente, sin pedir al usuario que reconstruya el historial.
5. Restricciones permanentes: no modificar la web pública libreriasaber.com.ar, no activar cobros, no publicar recepción de fotografías ni generar gastos sin autorización expresa.

**Importante:** Es una instrucción operativa que el asistente debe aplicar; no existe un aviso automático infalible de capacidad, por lo que corresponde anticiparse por longitud y complejidad del intercambio.
